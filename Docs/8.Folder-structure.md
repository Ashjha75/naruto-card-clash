will sit on disk. Part 2 is the order to actually write them in — not just
"which phase," but which file before which file, and why. Files tagged
`(have)` already exist in your repo from Day 1.

```
resources/

│   └── migration/
│       ├── V1__init.sql            # players, cards, player_cards, games, game_rounds
│       │                           # every table extending BaseEntity now needs created_by / updated_by UUID columns too
│       └── V2__seed_cards.sql      # 30 Naruto character cards
└── scripts/
    └── join_room.lua               # atomic check-and-join for private rooms
```

Note on the audit columns: `cards` is seeded by Flyway, not by a logged-in
player, so `created_by`/`updated_by` will be `NULL` for those rows (or a
fixed "system" UUID constant if you'd rather avoid nulls). Every other
table — `players`, `games`, `game_rounds`, `player_cards` — gets a real
player UUID once auth is wired up in Phase 3.

# PART 2 — Build Sequence

This is the actual order to create files in, inside each phase, so you're
never writing a class that references something that doesn't exist yet.
Numbering is continuous across the whole project — treat it as one
checklist. Concurrency-proof tests are written **inside** the phase that
produces the code they test, not deferred to a final testing pass — that's
deliberate, not a mistake in the ordering.

### Phase 1 — Foundation

1. `application-dev.yaml`, `application-test.yaml`, `application-prod.yaml`
2. `common/entity/BaseEntity.java` — nothing else can be written until this exists
3. `common/dto/ApiResponse.java`
4. `common/dto/ErrorResponse.java`
5. `common/dto/PageResponse.java`
6. `common/exception/ApiException.java` — base class before its subclasses
7. `common/exception/ResourceNotFoundException.java`
8. `common/exception/UnauthorizedActionException.java`
9. `common/exception/GameException.java`
10. `common/exception/MatchmakingException.java`
11. `common/exception/GlobalExceptionHandler.java` — needs steps 3–10 to exist first
12. `common/constant/CacheNames.java`
13. `common/constant/RedisKeys.java`
14. `common/util/RoomCodeGenerator.java`
15. `common/audit/SpringSecurityAuditorAware.java` — safe to write now; only becomes functionally meaningful once Phase 3 populates the SecurityContext
16. `config/JpaAuditingConfig.java`
17. `db/migration/V1__init.sql` — write last in this phase, once every entity's fields are known
